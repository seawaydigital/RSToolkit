# Defence Institution Tracker data

The data behind the toolkit's Defence Institution Tracker (`#defence-tracker`). One JSON file per institution, plus snapshots of the official lists it checks. Dataset © 2026 Andrew Austin, [CC BY 4.0](LICENSE).

The rules here are enforced by `tests/tracker-data.test.mjs` and `validateRecord()` in `src/tools/compliance/defence-tracker/lib/schema.js`. Run `npm test` after any edit.

## Layout

| Path | What it is |
|---|---|
| `institutions/<id>.json` | One institution. The file name is its id, and the id is its permanent permalink (`#defence-tracker/<id>`). Never rename one. |
| `listings/us-csl.json` | US Entity List, Military End-User List and SDN entries for research bodies in China, Russia and Iran. Generated by `npm run tracker:sync`. |
| `listings/ca-sanctions.json` | Consolidated Canadian Autonomous Sanctions List entities (research bodies in China, Russia and Iran). Generated by `npm run tracker:sync`. |
| `listings/us-1286.json` | US DoD Section 1286 list. Maintained by hand from the official PDF. |
| `listings/jp-meti-eul.json` | Japan METI End User List. Maintained by hand. |
| `meta.json` | Dataset version (`YYYY.MM`), rubric version, licence holder, the date the NRO list was last checked, attributions. |
| `changelog.json` | Dataset-level changes, newest first. |
| `index.js` | Builds the dataset in the browser (Vite). |
| `enabled.js` | Whether the tracker is switched on (`ENABLE_DEFENCE_TRACKER` in `src/siteConfig.js`). |

Canadian NRO listings come from `src/data/nroData.js`, the same data NRO Lookup uses. Institutions known only from a list snapshot get a minimal "listing-only" record at load time, so they need no file.

## Record statuses

- **`seed`**: created from the MISP galaxy list. Its MISP fields live in `seedNotes`, which is never displayed. Not researched.
- **`listing-only`**: known from an official list only. Not researched.
- **`verified`**: researched, with sourced evidence. Rated by the whole rubric.

Only verified records carry `evidence`. A record not researched yet is rated by the official lists alone (rubric 1.1): High, marked "from official lists", when any checked list names it, with each listing shown as evidence; "Not yet rated" when none does. Verifying a record replaces that with the rubric's rating of the profile. No one writes a rating by hand.

## Rules for verified records

- **Write every evidence summary in your own words.** Never copy ASPI's text (the MISP descriptions were never imported for this reason) or anyone else's.
- **Subunits** are `{ "name", "zh", "kind" }` with kind `campus`, `hospital`, `institute` or `lab`. Add `"match": true` only to a unit whose name alone identifies the parent (a named hospital such as 西京医院 Xijing Hospital): the batch check then matches it to the parent. Never mark campuses or generic names (口腔医院, 理学院).
- **Topics** are STRA category or subcategory ids from `src/data/straData.js` (`advanced-weapons`, `uncrewed-vehicles`), added only where a source shows research in that area. MISP's topic names in `seedNotes` ("Cyber") are not ids.
- **Every evidence item cites at least one source** from the record's `sources`, and gets the NSGRP Annex B questions it supports (`2.1` state influence, `2.2` misconduct or lack of transparency, `2.3` military or government ties).
- **Every source gets an archive entry**: `"archive": { "url": "https://web.archive.org/…" }`, or `"archive": { "unavailable": "<reason>" }` when no archive could capture it.
- **Never name individual people.** Describe roles, not names.
- **Word allegations as reported** ("reported by …"), and cite the report.
- **Set `status: "verified"`, `verifiedOn`, and append to `history`.** If you override the rubric's rating, move it one level at most and give `rating.overrideReason`.

See `docs/tracker/research-playbook.md` for the full process.
